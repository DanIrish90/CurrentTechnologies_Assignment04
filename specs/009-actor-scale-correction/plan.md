# Implementation Plan: Actor Scale Correction

**Branch**: `009-actor-scale-correction` | **Date**: 2026-10-16 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/009-actor-scale-correction/spec.md`

## Summary

Reduce the already corrected player and civil-servant presentation by an additional factor of two while keeping actor world anchors and gameplay coordinates unchanged. The implementation will centralize the actor scale profile, create quarter-sized pixel-sharp animation frames, use an `8x10` player collision body, and use a `12x15` civil-servant presentation target. Movement, map collision, interactions, camera bounds, and actor foot-position ordering remain authoritative in world coordinates.

## Technical Context

**Language/Version**: Python 3.12+

**Primary Dependencies**: Pygame-ce for image surfaces and rendering; existing project dependencies only.

**Storage**: N/A; actor scale values are runtime configuration and existing asset files remain the source artwork.

**Testing**: pytest, including headless Pygame tests and existing gameplay regression tests.

**Target Platform**: Desktop Windows/Linux, offline-first.

**Project Type**: Single-player desktop game with separated game logic and presentation modules.

**Performance Goals**: Preserve the existing 60 FPS target; scaling should occur once when animation frames are loaded, not repeatedly for every rendered frame.

**Constraints**: Preserve 32x32 map tiles, 1920x1088 world bounds, authored spawn and interaction coordinates, pixel-sharp edges, foot anchoring, polygon/rectangle collision, non-solid servants, and frame-rate-independent movement.

**Scale/Scope**: One player actor, four possible civil-servant actors, 84x128 source animation frames reduced to exactly 21x32 presentation frames, `8x10` player collision body, and `12x15` servant presentation targets.

## Phase 0: Research Decisions

Research is recorded in [research.md](research.md). The decisions are:

1. Scale animation surfaces once at load time using nearest-neighbor behavior to final `21x32` frames.
2. Keep logical collision dimensions independent from source sprite dimensions.
3. Anchor both actor types by their world foot point after scaling.
4. Validate source frame layouts before scaling so malformed assets fail clearly.
